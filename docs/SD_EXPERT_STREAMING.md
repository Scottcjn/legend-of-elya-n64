# SD-card expert streaming — probe spec and tiered design

**Summary.** Cart PI DMA hides a 1 MB expert completely (F-R028: steady-state `ec_acquire` ~100 cycles, switch 7.53M). SD does not obviously, for a structural reason: in libdragon's libcart, `edx_card_rd_dram()` loops per 512-byte sector — busy-poll the DAT lines, a *blocking* `__cart_dma_rd()` of 512 B, then 8 B of CRC — so 1 MB is ~2048 synchronous round trips with the CPU pinned, not one async transfer. Worse, `__cart_acs_get/rel()` reprograms the PI BSD domain timing registers around every call, so an SD read is **not safe to overlap an in-flight ROM expert DMA**. There is a second path: `edx_card_rd_cart()` hands the EverDrive its own DMA engine (`EDX_DMA_ADDR/LEN`) to stream SD → cart SDRAM while the CPU polls a status bit, after which the normal async PI DMA moves cart → RDRAM. `sd_probe.c` measures both before the design commits. I ran nothing.

## sd_probe.c

Same shape as `ec_probe.c`: one real model, the same 16 generated tokens per arm, ISViewer lines, and a token-equality check that voids the run if any arm perturbs the model. Reads use the real 1,048,592 B expert stride.

libcart's `cart.h` is **not** installed in the toolchain's `include/` (verified: `cart_init`, `cart_card_init`, `cart_card_rd_dram`, `cart_card_rd_cart` are all `T` in `libdragon.a`, header absent). Declare them in `src/sd_cart.h`, generated by `tools/gen_sd_cart.py` from libdragon's `src/libcart/cart.h` — no hand-kept second copy of someone else's ABI.

**Guards that must fire before any timing prints.**
- `cart_init() < 0` or `cart_card_init() != 0` → print `SD ABSENT type=%d` and `SD_DONE`, and **no** throughput lines. A missing card must not read as fast.
- Every arm pre-fills its destination with `0xA5A5A5A5`, then compares CRC-32 of the 1 MB against the same expert read from ROM (the bank ships in the probe ROM as well as on the card): `SD BYTES ok|DIFF|CANARY`. `DIFF`/`CANARY` voids the run. This is the F-R027 open-bus lesson made structural.
- The SD manifest's magic/count/stride must equal the ROM bank header's.

**Arms** (`run_arm(name, mode)`), one 1 MB expert per token, 16 tokens:

| arm | what it does |
|---|---|
| `BASE` | generation only, no SD traffic — the floor |
| `BLOCK` | `cart_card_rd_dram()` of 1 MB before each token |
| `FATFS` | `fopen("sd:/elya/e%02u.sgai")`/`fread` of the same 1 MB before each token |
| `HIDE` | `SD_CHUNK` sectors per slice, sliced between tokens, remainder drained after |
| `STAGE` | `cart_card_rd_cart()` SD→cart SDRAM, then `ec_request`/`ec_acquire` around the token |

Each prints `SD <arm> cp0=%u vbl=%u bytes=%u sectors=%u crc=%08x`; once, `SD INIT cart_init=%u card_init=%u mount=%u` and `SD CRCCOST cp0=%u` for one 1 MB CRC-32, so verification is priced rather than assumed free.

**Thresholds, fixed before the run.** One token ≈ 170 ms (F-R028's 5.87 tok/s).
1. Init (`cart_init`+`cart_card_init`+mount) **< 500 ms** ⇒ boot-time only.
2. `BLOCK` **≥ 2 MB/s** (1 MB ≤ 500 ms). < 1 MB/s ⇒ SD is a promotion source only, never a live expert source.
3. `FATFS` ≥ 70% of `BLOCK` ⇒ use stdio; below that, stream raw sectors from an extent map resolved once at boot.
4. `HIDE` ≤ **BASE + 10%** ⇒ chunked SD hides (F-R027: `HIDE` +0.84%, `BLOCK` +11.0%). ≥ 50% of `BLOCK`'s excess ⇒ it does not hide.
5. `STAGE` ≤ BASE + 10% ⇒ the two-stage path is the design. It is the only arm whose SD phase is plausibly free, and the one I expect to win.

`make sdprobe` mirrors `ecprobe`: `sd_probe.o` built `-DUSE_RSP_MATMUL -DRSP_MM_EPI_OVERLAP`, linked with `nano_gpt_ec.o`, `matmul_rsp2_ec.o`, `rsp_mm2_ovl.o`, `expert_cache.o`, and **without** `-DNDEBUG` (libdragon's SD FatFs lives behind `#ifndef NDEBUG`). Log: `probe/sd_probe_<date>.log`.

## Tiered design

- **Tier 2, RDRAM:** unchanged — 2 × 1 MB `ec` slots + KV + framebuffer.
- **Tier 0, cart ROM (≤64 MB X7):** router, dense fallback, ~40 hottest experts at the uniform `ec_init()` stride. Today's acquire path untouched.
- **Tier 1, SD:** the whole library — `sd:/elya/e%02u.sgai` plus `sd:/elya/bank.idx` (magic, count, stride, per-expert length and CRC-32), emitted by `training/make_moe_bank.py`, which already lays the ROM bank: one generator, one truth, extended with a `tier` field. `gen_moe_router.py` keeps emitting `moe_router.h` from `moe_shards.py`. Neither is hand-edited.
- **Resolution:** `expert_off[]` gains a parallel `expert_src[]` (ROM|SD) filled from `bank.idx` at boot. SD experts take the measured winning path; ROM experts keep today's async DMA.
- **Promotion:** acquire counts persist to `sd:/elya/heat.bin`. An expert crossing K acquires is copied once SD → the free tail of EverDrive SDRAM above the ROM image (`cart_card_rd_cart`), CRC-verified against `bank.idx`, and its `expert_src[]` flipped to ROM. Demotion is LRU on the same counts. Promotion runs only in a dialogue-idle frame, never mid-token.

## What I did NOT verify

- I ran nothing. No number here is measured; all cited figures are quoted from F-R027 / F-R028 / C028.
- Whether ares emulates an EverDrive SD card. If not, `cart_init()` returns `CART_NULL` and this probe runs on hardware only — hence the ABSENT guard.
- Actual SD throughput on the X7, raw or via FatFs, and its card dependence.
- Whether `cart_card_rd_cart()` genuinely frees the CPU (I read the poll loop, I did not time it), or can be polled cooperatively instead of spun on.
- Whether EverDrive SDRAM above the ROM image is writable and PI-readable at the addresses promotion assumes. `cart_size` reports SDRAM size; I tested nothing.
- Whether `__cart_acs_get()`'s PI timing reprogramming corrupts an in-flight `ec` DMA or merely serialises it. `HIDE`/`STAGE` are untrustworthy without the CRC check for exactly this reason.
- `fat_disk_read_sd` routes to `cart_card_rd_dram` only when `PhysicalAddr(buff) < 0x00800000`. Static BSS slots should satisfy this; I did not check the linker map.
- The 170 ms/token figure is derived from F-R028's vblank count, not re-measured.
